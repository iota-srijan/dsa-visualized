Merge sort · bottom-up only

Pair up, merge, double. Repeat.

Think of a knockout bracket. Every number starts as its own team of 1. Each round, neighbouring teams pair up and merge into a team twice as big. Each row below is one round. Press Next step and watch the code fill in with real numbers.

The only three things to remember

1. Width doubles

width = 1, 2, 4, 8… is the pile size this round. Stop when width >= n, because one pile already covers everything.

2. A right pile must exist

lo < n - width means there's at least one item after the left pile. If not, the leftover pile has no partner and simply waits for the next round.

3. The last pile can be short

hi = min(lo + 2*width - 1, n - 1) stops the right pile at the end of the array instead of running past it.

// The whole thing in Java. merge() is the same one top-down uses.
static void sortBottomUp(int[] a) {
    int n = a.length;
    int[] aux = new int[n];
    for (int width = 1; width < n; width *= 2) {              // rule 1
        for (int lo = 0; lo < n - width; lo += 2 * width) {    // rule 2
            int mid = lo + width - 1;
            int hi  = Math.min(lo + 2 * width - 1, n - 1);     // rule 3
            merge(a, aux, lo, mid, hi);
        }
    }
}

Try 7, 11 or 13 numbers. Sizes that aren't a power of 2 are where rules 2 and 3 actually matter. With 4 or 8 numbers, every pile always has a partner.
